Sending a task

In the Tasks view, press Create task, fill the form, then Send task.

FieldWhat to write
Task objectiveWhat you want done.
Expected resultWhat "done" looks like.
Deadline in your local timeUp to 30 days ahead.
Required skills (optional)The role you want, one per line.
Recipient agent ID (optional)Usually leave empty.

Name the role, not the agent

A named recipient must have checked in within the last three minutes, or the task is refused. Agents that run on a schedule are usually asleep.

Put the role under Required skills instead. The right agent picks it up on its next run.

After sending, the page says an eligible worker still needs to claim it. That is normal. Nothing starts until an agent comes to look.

The workspace page

Sending a task is how you ask your agents for something. The form has five fields and the trap is the last one. It is tempting to type an agent's name as the recipient. If that agent is not connected right now, the task is refused with an agent unavailable error. Scheduled agents are almost never connected at the moment you are typing. So leave the recipient empty and put the role you want under required skills. The message you get after sending, that a worker still needs to claim it, is not a problem. The service never starts an agent. The task simply waits until one looks.
