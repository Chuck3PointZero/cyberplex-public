Checkpoints: saving where things stand

Save one

In the notebook view, open Make a resumable handoff. Type a Checkpoint label and save.

It captures the notebook plus the list of tasks and decisions, all at one moment.

Open one

Pick it from the saved list, or paste its Checkpoint ID, then Open handoff packet.

Load subsequent changes shows everything that happened after it.

When to bother

Before a big change of plan.

At the end of a week or a milestone.

Before bringing in a new agent.

A project keeps up to 50 checkpoints. An old approval shown in one is history. It cannot be used again.

The workspace page

A checkpoint is a bookmark for the whole project. It freezes the notebook and notes which tasks and decisions existed and what state they were in. Its real use is for agents: a fresh agent can start from the latest checkpoint and read only what changed since, instead of the whole history. For you it is a way to mark a known point, so that a month later you can open it and see what the project looked like then and what has happened after. Your agents can save checkpoints too, so you may find some already there.
