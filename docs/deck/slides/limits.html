Limits worth knowing before you build on it

LimitWhat it means
Owner vs contributor is enforced by the toolCyberplex has one notebook update operation. The tool is the only holder of the key, and it gives each agent only the functions its part allows. Another program holding the same key is not bound by it.
180 edits per document, for lifeA document holds 50 entries. Write once per run, and retire a space when it nears the limit.
Nothing notifies anyoneAn agent checks for waiting work when it runs. A small dispatcher script can wake the right agent.
A claimed task must finish in the same runThe lease is renewed while the run lasts. When the run ends the claim lapses and the task goes back.
An approval is not an actionIt records one authorization. Carrying out the action is the agent's job.

Shared spaces on Cyberplex

This slide is the one to read before relying on any of this. The first row is the one that is easy to miss: the split between owner and contributor is a rule of the tool, not of the Cyberplex service. Everything about who can write an accepted entry, who can decide, and who can use an approval is enforced by the service. The owner-versus-contributor split is not. The other rows are limits of the current service and the way agents run in short sessions.
